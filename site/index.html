Refuser les cookies, à quel prix ?

La CNIL demande que refuser soit aussi simple qu'accepter. Voici ce qu'on a constaté en cliquant sur « refuser ».

21 sites où refuser, c'est s'abonner ou se connecter

Sur ces sites, le seul bouton de refus mène vers une page d'abonnement, de paiement ou de création de compte : c'est un « mur de cookies » (accepter ou payer). La CNIL ne l'interdit pas par principe, mais l'examine au cas par cas : l'alternative doit être réelle, son prix raisonnable, et l'éditeur doit pouvoir le justifier. Ce qu'on ne peut pas affirmer
  • Le refus est cliqué par un robot (règles autoconsent). Sur 139 sites, le choix enregistré contredit le choix demandé : le robot a pu se tromper de bouton. Ils sont marqués « choix non vérifié » et exclus des comparaisons, sans être accusés.
  • Quand le robot n'a pas trouvé de bouton « refuser », on ne sait pas si le bouton n'existe pas ou si les règles ne le connaissent pas. Ces sites ne sont pas listés ici.
  • La page d'arrivée après un refus est relevée automatiquement. Les cas de 20 Minutes et du Figaro ont été vérifiés à l'œil sur capture : leur bouton de refus s'intitule « Refuser et s'abonner ».

Que faire ?

En tant qu'internaute

  1. Refusez. C'est le geste qui compte le plus : sur un site de médias, la page refusée pèse en médiane 8 fois moins lourd. Pour le site médian, c'est ×1,4 ; pour un site sur quatre, plus de ×3,9.
  2. Bloquez les tiers. Un bloqueur comme uBlock Origin (ou uBlock Origin Lite sur Chrome) empêche ces scripts de se charger, donc d'occuper de la mémoire. Nous ne l'avons pas mesuré : c'est la prochaine étape du projet.
  3. Laissez le navigateur décharger les onglets. Chrome : Paramètres › Performances › Économiseur de mémoire. Edge : onglets en veille. Firefox décharge les onglets quand la mémoire manque.
  4. Fermez les onglets lourds. Cherchez vos sites dans le classement : un onglet de média ouvert toute la journée peut occuper plus de 1 Go.

Si un site ne vous laisse pas refuser

  1. Écrivez à son délégué à la protection des données (son adresse est dans la politique de confidentialité du site), en citant la règle de la CNIL : refuser doit être aussi simple qu'accepter.
  2. Sans réponse sous un mois, ou si la réponse ne vous convient pas, déposez une plainte auprès de la CNIL. Joignez une capture de la bannière et la date.

Si vous faites des sites

  1. Mesurez votre page avec le même outil : npm ci, npx playwright-core install chromium, puis node src/measure.js https://votre-site.fr accept (et refuse). Le mode d'emploi est dans le dépôt.
  2. Ne chargez rien avant le consentement, et rien de soumis au consentement après un refus.
  3. Regardez vos tiers un par un : sur les pages lourdes, quelques régies d'enchères pèsent plus que tout le reste de la page.
  4. Fixez-vous un budget de mémoire et suivez les référentiels d'écoconception : WSG du W3C, RGESN.

Pour aider le projet

  • Une erreur sur votre site, un site à ajouter : ouvrez un ticket.
  • Réutilisez les données (CSV ci-dessus, licence CC BY 4.0) pour vos articles ou vos recherches. La mesure est refaite chaque mois.

Comment on a mesuré

  1. La liste : les origines les plus visitées en France selon le Chrome UX Report (octobre 2026), une par domaine, sans les pages de connexion ni les sites adultes.
  2. Le navigateur : Chromium 134 sans affichage, avec l'isolation par site activée (chaque site tiers dans son propre processus) et un agent utilisateur Chrome standard qui se déclare comme robot de mesure. Aucun contournement des protections anti-robots.
  3. Les cookies : une première visite accepte ou refuse la bannière automatiquement (règles autoconsent de DuckDuckGo), puis la mesure se fait dans une visite neuve qui garde ce choix. Quand le site suit le standard TCF, on relit le choix enregistré pour vérifier. On note aussi la page où mène le clic.
  4. La visite : chargement, défilement jusqu'en bas, puis 60 secondes sans rien faire. On a vérifié sur 12 sites que la mémoire est stable à ce moment-là.
  5. La mesure : l'empreinte mémoire privée de chaque processus de la page, lue par l'outil de traçage interne de Chrome. Un site tiers isolé dans son propre processus est attribué exactement ; le JavaScript de la page principale est attribué script par script.
  6. La répétition : 3 mesures par site et par choix, jusqu'à 5 tant que l'écart dépasse 5 %. On garde la médiane.

Les limites

  • 173 sites sur 1000 n'ont pas pu être mesurés : ils ont bloqué le robot (133 refus d'accès, 27 captcha, 5 page de blocage, 4 vérification anti-robot, 2 service indisponible, 2 trop de requêtes).
  • Les pages avec beaucoup de pub varient : la moitié des mesures varient de moins de 2 %, mais 108 combinaisons site × choix varient de plus de 20 %, selon les publicités servies.
  • Une partie de la mémoire n'est pas attribuée : dans la page principale, seul le JavaScript est attribué à son auteur ; le reste (affichage, images, structure) est compté pour le site lui-même.
  • Une seule configuration : un Chromium sur Linux, un écran 1366×768, une connexion française. Un autre navigateur ou un téléphone donneraient d'autres chiffres, mais les écarts entre sites restent comparables.
  • Seule la page d'accueil est mesurée, pas les articles ni les vidéos.

Le code, les règles, la liste et les résultats complets sont publics : github.com/Kenshin9977/ram-blacklight.

Et ce site ?

Il suit les recommandations d'écoconception (WSG du W3C, RGESN, 115 bonnes pratiques) qui comptent pour la mémoire et le processeur :

  • une seule page HTML statique, sans framework, sans police téléchargée, sans image ;
  • aucun script tiers : ni mesure d'audience, ni bannière de cookies (il n'y a pas de cookie) ;
  • les graphiques sont du HTML et du CSS, sans bibliothèque ni canvas ;
  • pas d'animation ni de minuterie : rien ne tourne quand vous ne faites rien ;
  • les données du classement (89 ko) ne sont chargées qu'à l'approche du tableau, qui n'affiche que 50 lignes à la fois ;
  • les sections hors de l'écran ne sont pas mises en page tant qu'on n'y arrive pas.

Résultat : 35 Mo de RAM, mesuré avec le même protocole, contre 154 Mo pour la page médiane du top 1000.
